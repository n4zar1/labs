La foto de perfil

Medio · ~12 min · Basado en el vídeo «Esto no es una foto de perfil. Es una puerta trasera (subida de archivos)».

El caso. Huellas Felices, la web de una protectora de animales ficticia (perfil.example), deja a sus voluntarios subir una foto de perfil. El lunes por la mañana alguien avisa de que la lista de voluntarios, con sus correos y teléfonos, circula por un foro. La administradora, Marta, te pasa el registro del servidor web, lo que hay en la carpeta de subidas, los procesos que se abrieron en la máquina y el código que comprueba las fotos.

Tu misión: encuentra la «foto» que no era una foto, quién la subió, por qué la dejó pasar el filtro, qué ejecutó el servidor, qué se llevó el atacante y qué arreglo lo cierra. Chuleta: si una web guarda lo que subes sin comprobar qué es (CWE-434, «subida de archivos sin restricciones») y lo deja en una carpeta pública donde el servidor ejecuta los .php, un script con nombre de foto se convierte en una web shell: una puerta trasera que obedece órdenes por el navegador (MITRE ATT&CK T1505.003).

4 · El código que comprueba la foto y la configuración del servidor

// subir_foto.php (extracto)
$nombre = $_FILES['foto']['name'];          // el nombre que manda el usuario
if (strpos($nombre, '.jpg') !== false) {   // «¿lleva .jpg?»
    move_uploaded_file($_FILES['foto']['tmp_name'],
        '/var/www/html/uploads/' . $nombre);  // carpeta pública, mismo nombre
}

# nginx.conf (extracto)
root /var/www/html;
location ~ \.php$ {                        # cualquier .php, también en /uploads/
    fastcgi_pass unix:/run/php/php-fpm.sock;
}

Reto completado

Bandera:

Lo que haría Marta: borrar foto.jpg.php (después de guardar una copia para el análisis), buscar otros scripts en uploads/ y en el resto de la web, cambiar la contraseña de la base de datos que estaba en config.php, avisar a los voluntarios afectados y, si hace falta, a la autoridad de protección de datos. Para que no vuelva a pasar: lista de extensiones permitidas (.jpg, .png, .webp) comprobando el contenido real del archivo, un nombre nuevo generado por la web, guardar las fotos fuera de la carpeta pública (o en otro dominio) y que en uploads/ no se ejecute nada. Para vigilarlo: alerta por peticiones a .php dentro de /uploads/ y por el servidor web lanzando consolas (regla Sigma «Suspicious Process By Web Server Process»).
