La capa invisible

Medio · ~12 min · Basado en el vídeo «Pulsaste “Ver vídeo”… pero ese botón no era el que viste (clickjacking)».

El caso. Banco Ana, un banco ficticio (banco-ana.example). Miércoles 4/11. Varios clientes juran que no han hecho una transferencia de 500 € que aparece en su cuenta. Todos dicen lo mismo: «Solo pulsé “Ver vídeo” en una web de premios». Nadie les ha robado la contraseña y no hay virus en sus móviles. El banco te pasa el registro de su web, las cabeceras de dos de sus páginas, el código de la web de premios y el informe de un escáner.

Tu misión: descubre desde qué web se hizo, quién cayó, por qué funcionó y qué arreglo lo cierra. Chuleta: en un clickjacking una web carga otra web real dentro de un marco (iframe) invisible y coloca el botón de verdad justo encima de su botón cebo. Tu clic cae en la web real, con tu sesión abierta.

1 · Registro de la web (banco-ana.example) · 4/11, de 19:30 a 19:40

2 · Cabeceras de respuesta de dos páginas del banco

GET /login
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
X-Frame-Options: DENY
Strict-Transport-Security: max-age=31536000

GET /pagos/transferir
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Strict-Transport-Security: max-age=31536000
Set-Cookie: sesion=8f3a9c…; Secure; HttpOnly; SameSite=None

3 · El código de la web de premios (premios-gratis.example)

<h1>🎁 ¡Has ganado un premio!</h1>
<button id="cebo">▶ Ver vídeo</button>

<iframe id="capa"
  src="https://banco-ana.example/pagos/transferir?a=ES91…4821&importe=500">
</iframe>

<style>
  #capa  { position: absolute; top: 0; left: 0;
           width: 100%; height: 900px;
           opacity: 0; z-index: 2; }
  #cebo  { position: absolute; top: 610px; left: 200px;
           z-index: 1; }   /* justo debajo del botón «Transferir» */
</style>

4 · Escáner web (pasivo) · banco-ana.example

Alerta:    Missing Anti-clickjacking Header   (regla 10020-1)
Riesgo:    Medio
URL:       https://banco-ana.example/pagos/transferir
Detalle:   The response does not protect against 'ClickJacking' attacks.
           It should include either Content-Security-Policy with
           'frame-ancestors' directive or X-Frame-Options.
Fecha:     12/10 (informe sin revisar)

Reto completado

Bandera:

Lo que haría el banco: añadir Content-Security-Policy: frame-ancestors 'self' (o 'none') a todas sus respuestas, no solo a /login, y X-Frame-Options: DENY para navegadores antiguos; pasar la cookie de sesión a SameSite=Lax o Strict; pedir una confirmación de verdad (código en el móvil) para transferencias y cambios sensibles; bloquear la cuenta ES91…4821 e intentar recuperar las transferencias; avisar a los clientes afectados; crear una alerta para peticiones a /pagos/ con Sec-Fetch-Dest: iframe desde otra web; y revisar los informes del escáner, que llevaba avisando desde el 12/10.
